# Local trial in a consuming app: Track Recover

Nothing in this trial was committed, pushed, published or uploaded. Track Recover's Git working tree was clean before
the trial; its own repository now shows three modified files (see below).

## Why Track Recover
Five local apps use this library. Track Recover has a clean working tree, no existing UMP code (so managed consent is
the single consent owner), banner/native widgets, interstitial/rewarded/app-open flows, premium handling and
unsubscribe flows that must keep working when ads fail. It uses `AdsStatus.hybrid` (Google test units in debug builds)
and keeps its own release ad ids, which were not touched. On iOS it passes `AdsStatus.disabled`, so no ads or consent
run there.

## Exact local changes (Track Recover repo)
1. `pubspec.yaml`: a `dependency_overrides` block that points `admob_ads_manager` at the local library checkout and sets
   `google_mobile_ads: ^9.1.0` (the app's own `^8.0.0` constraint conflicts with the library's `^9.1.0`). The original
   Git dependency lines were not edited.
2. `pubspec.lock`: regenerated by `flutter pub get` (only `admob_ads_manager` and `google_mobile_ads` changed).
3. `lib/services/ads_service.dart` (new helpers and call sites):
   - `_adsReady()` waits at most 3 s for `AdsManager.instance.whenReady()` and returns false on timeout/error; every
     show path (`showAppOpenIfEligible`, `showPostOtpInterstitial`, `showPreUnsubscribeInterstitial`,
     `showInterstitialAction`, `showRewardedAction`) continues its normal flow (`onContinue` / return) when it is false.
   - `consentDebugSettings` passed to `AdsManager.init`, active only in debug builds and only when
     `--dart-define=UMP_TEST_DEVICE=...` is given (`UMP_EEA=true` forces the EEA geography).
   - Premium checks, frequency/interval rules, region-based release ids, iOS handling and all handlers' continuations are
     unchanged.
4. Tooling side effect: `flutter pub get` rewrote
   `ios/Runner.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved`; it was restored with
   `git checkout` and is not part of the trial.

## How to restore the original configuration
In the Track Recover repository:

```bash
git checkout -- pubspec.yaml pubspec.lock lib/services/ads_service.dart
flutter pub get
git checkout -- ios/Runner.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved   # if pub get changed it
```

## Status: build-verified only
Track Recover was **not run on a device**. Its release APK was built with the project's existing release signing config,
which is the **debug key**, so it is a compile check and must not be treated as a production release artifact or
uploaded anywhere. The trial changes are local, uncommitted and reversible (see above).

Blocker: the phone has the Play Store build of the app (`com.globe.track`, 3.0.7, code 32, Play-signed). The project
builds 3.0.5 (code 27) signed with the debug key, so installing would require uninstalling the Play version and
destroying its data. I did not do that. Ad flows of Track Recover were therefore **build-verified only**; behaviour was
exercised on the phone only through this library's example app.

## Behaviour notes found while reviewing the app (unchanged, for the owner)
- `showRewardedAction` calls `onContinue` from `onDismissed` whether or not a reward was earned (existing behaviour).
- The splash screen shows an app-open ad automatically, so with managed consent a first launch shows the consent form
  first; the app-open ad is skipped when ads are not ready within 3 s.
- Configure the AdMob GDPR/privacy message for the Android app before shipping managed consent, otherwise users in
  regions that require consent may never get `canRequestAds`.
- The native medium ad default height changed from 300 to a width-based 320-400 dp.
